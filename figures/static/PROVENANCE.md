# Static figures

Five of the paper's nineteen figures are **not** regenerated by this repository.
They are included here as single-page extracts from the camera-ready PDF, and this
file records what each one is and why it is static. Everything else in `figures/`
and `tables/` is a script that rebuilds its figure from the model, the cached
metrics in `data/results/`, or the asset bundle.

Each file is named `<figure>_p<page>.pdf`, where the page number is its page in the
camera-ready PDF. The page is extracted whole, so each file contains the figure
together with its caption and whatever body text shares the page.

| File | Paper | Why it is static |
|---|---|---|
| `fig01_overview_p3.pdf` | Figure 1 | Hand-drawn schematic of the analysis-by-synthesis pipeline. Drawn in a vector editor, not generated from code; no source file exists in any of the three working repositories. |
| `fig07_peripheral_pooling_p9.pdf` | Figure 7 | Foveated syntheses from the spatial-pooling branch. The branch itself ships (`utils/poolingregions.py`, `utils/gazewarp.py`), but no figure script for it survives, and see the warning below before enabling pooling. |
| `fig15_contrastive_clustering_p23.pdf` | Figure 15 | Clustering of contrastively-learned embeddings. Produced interactively in a notebook (`StaTexGramNet.ipynb` lineage); no script version exists. |
| `fig17_stat_contribution_p26.pdf` | Figure 17 | Percent contribution of statistics under the learned importance ordering. Same notebook lineage as Figure 15. |
| `fig18_spatiotemporal_filterbank_p26.pdf` | Figure 18 | Visualization of the spatiotemporal filter bank. The bank itself **is** reproducible: `scripts/build_video_filterbank.py` rebuilds it bit-for-bit (verified against the original to 8e-16). Only the 3D rendering of it came from plotting cells in `SpatiotemporalMochinutFilters.ipynb` that were not part of the generation path. |

## A warning about Figure 7's code path

`utils/poolingregions.py` carries a known defect. In `calcgramm`, the pooled branch
indexes `[0]`, which silently keeps only batch element 0 and discards the rest of
the batch. Every result in the paper used `use_pooling=False`, so nothing published
is affected, but if you turn pooling on, fix that indexing first. The comment at
the call site in `utils/stattexgramnet.py` says the same thing.

## Reproducing these five

Figures 15 and 17 depend on notebook state that was not preserved. Figure 1 is a
drawing. Figure 7 would need a figure script written from scratch against the
pooling branch, after the batch-indexing fix. Figure 18 needs 3D rendering code for
a filter bank that this repository can already rebuild.

If you want any of them regenerated rather than extracted, the missing piece in
each case is stated above; none of them is blocked on data.
